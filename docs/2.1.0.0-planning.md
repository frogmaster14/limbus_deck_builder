# 2.1.0.0 Planning

2.1.0.0은 새 기능을 무작정 붙이는 버전이 아니라, 현재 기능을 사용자 시점에서 다시 정렬하는 버전이다.

## 핵심 방향

- 사용자가 한 화면에서 지금 해야 할 일을 바로 알 수 있어야 한다.
- 화면마다 목적을 하나로 좁힌다.
- 필요한 정보는 남기되, 지금 작업과 직접 관련 없는 정보는 접거나 다른 화면으로 보낸다.
- 언제든지 다른 작업으로 이동할 수 있되, 현재 화면은 현재 작업에 집중하게 만든다.
- 필터 개선은 유저 피드백이 필요하지만, 먼저 피드백할 가치가 있는 완성도와 가능성을 보여줘야 한다.
- 베타 단계라도 사용자가 "이 정도면 의견을 남기면 좋아지겠다"라고 느낄 만큼 핵심 흐름은 정돈되어 있어야 한다.

## 반드시 먼저 정리할 것

1. 인격 필터링을 먼저 만든다.
2. 필터 기능은 완벽한 정답표가 아니라 베타 보조 기능이다.
3. 필터 분류는 다수 유저의 피드백으로 보정될 영역이라는 점을 사용자에게 자연스럽게 전달한다.
4. 화면 안에서 넓은 패널을 차지하는 기능은 목적별 화면이나 보조 창으로 분리한다.

## 작업 우선순위

### 현재 구현

- 덱 구성 화면을 중심 작업대로 사용한다.
- 전방/후방 슬롯을 누르면 작업대 위에 인격 선택 화면을 연다.
- 인격 선택 뒤 기존 20장 덱, EGO, 강화카드, 저장 상태로 돌아온다.
- 작업대에서 전방/후방 위치를 바로 교체할 수 있다.

### 지금 바로 할 수 있는 것

1. 인격 필터 데이터 구조를 정한다.
2. 현재 카드 필터와 같은 방식으로 인격 필터 UI를 붙인다.
3. 저장 목록과 저장 덱 보기의 역할을 더 분명히 나눈다.
4. 필터는 베타 보조 기능이며 피드백으로 개선된다는 안내를 개발자 노트나 화면 문구에 반영한다.
5. 2.1.0.0 통합 덱 작업대에 필요한 상태값과 화면 흐름을 설계한다.

### 바로 하면 위험한 것

1. 전방/후방 선택 화면과 20장 덱 구성 화면을 즉시 합치는 것.
2. PC UI를 유지한 채 모바일 화면만 억지로 맞추는 것.
3. 특수 키워드를 삭제하거나 데이터 구조를 한 번에 갈아엎는 것.
4. 카드 지식 패널을 실제 데이터 없이 먼저 만드는 것.

### 첫 구현 후보

첫 구현은 `인격 필터링`이 가장 좋다.

이유:

- 2.1.0.0 통합 덱 작업대에서도 그대로 필요하다.
- 인격 선택 팝업에도 그대로 재사용된다.
- 현재 필터 정확도가 완벽하지 않아도, 베타 피드백을 받는 구조와 잘 맞는다.
- 화면 구조를 크게 뒤집지 않고도 시작할 수 있다.

인격 필터링 다음에는 `저장 목록/보기 역할 정리`를 진행한다.

그 뒤에 `통합 덱 작업대`를 시작한다.

임시 인격 필터 기준:

- 현재 카드 태그에서 인격 소속 카드, 고유카드, 강화카드에 붙은 태그를 역산한다.
- 기본 카드는 같은 수감자의 모든 인격에 접근 가능하지만, 인격 자체의 기믹으로 보기엔 과할 수 있으므로 임시 인격 필터에는 넣지 않는다.
- 이 기준은 베타용이며, 실제 인격 운용 기믹은 유저 피드백으로 보정한다.

## 저장 목록

- 저장 목록은 덱을 서로 구분할 수 있을 정도의 정보만 보여준다.
- 목록 카드에는 덱 이름, 중심 필터, 전방/후방 인격 정도만 남긴다.
- 세부 설명, 20장 카드, EGO, 강화카드, 추가 키워드, 사용 방식은 `보기`에서 읽게 한다.
- `수정`은 통합 덱 작업대로 들어가게 한다.

## 덱 만들기

- 전방/후방 선택과 20장 덱 구성을 한 작업대로 합친다.
- 전방/후방 패널을 누르면 해당 위치에 넣을 인격을 고르는 검색/선택 창을 연다.
- 인격 선택 창은 현재 인격 선택 화면의 장점을 유지하되, 도감 수준의 필터를 제공한다.
- 전방/후방 스왑 버튼은 통합 작업대에 둔다.
- 카드 썸네일은 오른쪽 확대 패널이 있으므로 구분 가능한 최소 크기와 정보만 보여준다.

## 카드 지식 패널

Minecraft 모드 JEI처럼, 어떤 화면에서든 카드에 마우스를 올리거나 선택한 상태에서 특정 키를 누르면 해당 카드의 추가 설명을 열 수 있게 하는 기능을 장기 목표로 둔다.

- 기본 정보는 카드 이미지와 현재 필터 데이터에서 가져온다.
- 추가 설명, 사용 방식, 예시, 주의점은 운영진이나 숙련 유저 피드백을 모아 수동으로 작성한다.
- 지금 당장 구현할 기능은 아니며, 먼저 UI 구조와 데이터 구조가 안정된 뒤 추가한다.
- PC에서는 `호버 + 단축키`가 자연스럽다.
- 모바일에서는 호버가 없으므로 `길게 누르기`, `상세 버튼`, `선택 후 상세 열기` 같은 별도 조작이 필요하다.

## 모바일 대응

모든 기능은 가능하면 모바일에서도 구동되어야 한다. 다만 현재 PC 기준의 3열 패널, 호버 확대, 긴 필터 패널 구조를 그대로 모바일에 옮기면 사용성이 무너질 가능성이 높다.

모바일 방향:

- 모바일은 세로 화면을 우선 기준으로 설계한다.
- 한 화면에 모든 패널을 동시에 보여주려 하지 않는다.
- 주요 작업 영역을 하나씩 전환하는 구조가 필요하다.
- 모바일에서는 일부 동시 정보 노출을 포기하는 대신, 버튼으로 기능을 열고 닫으며 현재 작업을 화면 전체로 크게 보여준다.
- 오른쪽 확대 패널은 모바일에서 하단 상세 패널이나 전체 화면 미리보기로 바꾼다.
- 필터는 항상 펼쳐진 사이드 패널이 아니라, 버튼을 눌러 여는 필터 화면이나 하단 시트로 다룬다.
- 카드 선택은 작은 썸네일 그리드와 선택된 카드 상세 보기의 왕복이 되도록 한다.
- 호버로 가능한 기능은 모바일 대체 조작을 반드시 둔다.
- 세로 화면에서는 긴 스크롤과 하단 고정 조작 버튼을 적극 활용한다.
- 가로 화면에서는 좌우 엄지손가락으로 조작하기 쉬운 양손 배치를 보조 모드로 고려한다.
- 모바일 화면 전환은 `덱 요약`, `카드 목록`, `필터`, `상세 보기`, `저장`처럼 명확한 모드 버튼으로 나눈다.

모바일에서 특히 다시 설계해야 할 기능:

- 카드 확대 미리보기
- 카드 지식 패널
- 인격 선택 팝업
- 카드 삽입 팝업
- 긴 필터 목록
- 저장 덱 상세 보기

## 특수 키워드 판단

현재 `특수 키워드`는 계속 늘어날 가능성이 높아서, 지금처럼 필터 하단에 길게 붙이는 방식은 오래 버티기 어렵다.

판단은 3-2안을 기본으로 한다.

- `특수 키워드` 체제는 유지한다.
- 다만 일반 키워드 밑에 계속 늘어뜨리는 방식은 피한다.
- 데이터 관리는 `고유카드`와 `스택/상태/공용 특수카드`를 구분해서 한다.
- 인격별 폴더에서도 고유카드와 스택카드, 상태카드를 나누어 관리하는 방향이 좋다.
- 여러 인격이 같이 쓰는 `진동폭발`, `투. 식.`, `못` 같은 항목은 공용 특수카드로 둔다.

이유:

- 특수 키워드를 완전히 지우면 화면은 단순해지지만, 공용 특수카드 검색성이 사라진다.
- 반대로 지금처럼 계속 아래에 붙이면 UI가 무너진다.
- 따라서 데이터 체계는 유지하고, 화면에서는 접힌 보조 필터나 별도 필터 그룹으로 다루는 편이 낫다.

## 보류할 것

- 특수 키워드의 최종 UI 배치는 인격 필터링과 통합 덱 작업대 구조가 잡힌 뒤 결정한다.
- 필터 명칭과 포함 기준은 베타 피드백을 받아 계속 수정한다.
- 카드 지식 패널은 사용자 기입 데이터가 쌓인 뒤 설계한다.
- 모바일 대응은 2.1.0.0 정보 구조가 정리된 뒤 별도 레이아웃 단계로 진행한다.
